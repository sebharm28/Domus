================================================================================
V2 — HOUSEHOLD ACCOUNTS (Sep 2026)
================================================================================

Problem v1 left open
--------------------
Join codes required owner approval; no real login; device trust only.
Roommates needed password/OTP verification and multi-device login for the same
member entity.

Model
-----
  **Household account** = apartments row (+ invite_token, password_hash)
  **Member entity**     = users row + apartment_members (admin | member)
  **Device session**    = device_sessions (Bearer token per device)

Default seed (empty DB)
  Household: Karl-Marx-Allee 5
  Admin:     Sebastian (member #1)
  Password:  test1234

Flows
-----
  **Create household** — name + your name + password → session token
  **Join (new member)** — invite link (?invite=token) + name + password or OTP
  **Log in (existing)** — invite link + pick member + password or OTP
  **Entity switcher** — header chip; multiple (household, entity) pairs per device

Admin powers
  Rename / remove members (revokes their sessions)
  Transfer admin; auto-promote sole co-member when admin leaves
  Regenerate invite link; generate 15-min OTP
  Set household password
  Export household JSON (optional anonymize history); import into new household

API (v2)
  POST /api/auth/create-household, /api/auth/join, /api/auth/login, /api/auth/entities
  GET  /api/auth/invite?token=
  POST /api/household/generate-otp, set-password, regenerate-invite
  POST /api/household/transfer-admin, rename-member
  GET  /api/household/export?anonymize=0|1
  POST /api/household/import
  Auth header: Authorization: Bearer <session_token>

How to test v2
--------------
  PYTHONPATH=src python ui/server.py
  1. Open http://127.0.0.1:8765 — entity switcher or create/join form
  2. As admin → Household → copy invite link; share with roommate
  3. Roommate opens link → Join → name + password test1234 (or OTP from admin)
  4. Second device → Log in → pick existing member + password/OTP


================================================================================
V1 — JOIN CODES (Aug 2026, legacy)
================================================================================

Problem
-------
Profiles were created with a free-text apartment string. There was no shared
identity for a household, no way for a second person to join the same apartment
reliably, and profile registration failed in the UI (missing db import).

What we implemented (v1)
------------------------

Schema (wave 6 migration):
  apartments.join_code          — 13-char public ID
  apartments.created_by_user_id — first owner
  apartment_members             — user_id, role, status, timestamps

Roles & status:
  role:   owner | member
  status: active | pending | removed

Flows:
  **Create apartment** (profile picker → “Create apartment”)
    → new user + apartment row + join code + owner membership (active)

  **Join apartment** (profile picker → “Join with code”)
    → pending membership until owner accepts (v1 only)

  **Accept / Kick** (Household → Apartment panel, owner only)

v1 still works for legacy join codes; v2 OTP/password join skips pending state.
