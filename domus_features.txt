DOMUS — FEATURE GUIDE
=====================

Domus is a Telegram household assistant for a shared group chat (two users,
two apartments). Messages must start with the wake word "Domus" so the bot
knows when to respond. The bot uses OpenRouter for natural-language intent
parsing when an API key is set, and falls back to built-in rules otherwise.
Data is stored locally in SQLite (data/domus.db).


HOW TO TALK TO DOMUS
--------------------
Every command starts with "Domus" in the group chat, for example:
  Domus, add milk to the list

Social / meta:
  Domus, hello
  Domus, thank you
  Domus, help
  /start and /help also work as Telegram commands (no wake word needed).


================================================================================
IMPLEMENTED FEATURES
================================================================================


1. SHARED TO-DO & SHOPPING LIST
-------------------------------
Add, list, complete, and remove tasks. Items are shared for everyone in the
group chat. Tasks can have categories and due dates.

Categories: shopping, household, admin, maintenance, personal, general
(shopping is inferred automatically for grocery-style items).

Examples:
  Domus, add milk to the list
  Domus, we need butter and eggs
  Domus, add pay rent by friday category admin
  Domus, please add going to the bank to the todo list. Have to do it tomorrow
  Domus, what's on the list?
  Domus, show me the shopping list
  Domus, check off milk
  Domus, I bought the milk
  Domus, remove milk from the list
  Domus, we do not need butter anymore

Natural-language parsing handles casual phrasing, quoted items, relative dates
(tomorrow, by friday), follow-up sentences ("Have to do it tomorrow"), and
multi-item messages (e.g. "butter and eggs").

Todo-list adds infer category from the task (e.g. "going to the bank" → admin).
Shopping-list adds still default to category shopping.


1b. TASK CORRECTIONS (update_todo)
----------------------------------
Fix a recent task when you misspoke or the bot misunderstood — handled by
rules (not OpenRouter) so corrections are reliable.

Examples:
  Domus, I said the task is for tomorrow
  Domus, I meant going to the bank
  Domus, have to do it tomorrow

What happens:
  - Sets due date on the most recent open task (or a matching task by name)
  - "I meant …" also removes obvious mistaken entries (e.g. bad LLM adds)
  - Resets reminder_sent when the due date changes


2. ONE-TIME DUE-DATE REMINDERS
------------------------------
Tasks with a due date trigger an automatic Telegram reminder on or before
that date. Each task is reminded once (reminder_sent flag).

Examples:
  Domus, add call landlord by tomorrow category admin
  (Scheduler checks every 60 seconds and notifies subscribed chats.)


3. RECURRING REMINDERS
----------------------
Repeating household reminders run on a schedule without LLM cost. Supported
patterns: daily, weekly (by weekday), monthly (by day of month).

Examples:
  Domus, remind us every Tuesday to take out the trash
  Domus, remind me on the 1st of each month to pay rent
  Domus, remind us daily to water the plants
  Domus, list recurring reminders
  Domus, remove the take out the trash reminder

After a recurring reminder fires, the next due date is calculated automatically
(e.g. next Tuesday, next month on the 1st).


4. DAILY BRIEFING
-----------------
On-demand summary of the day, plus an automatic morning briefing at 08:00
(local time, configurable via BRIEFING_HOUR in .env).

The briefing includes:
  - Tasks due today
  - Overdue tasks
  - Shopping list preview
  - Other open tasks (up to 3)
  - A meal idea for the current time of day

Examples:
  Domus, what's on today?
  Domus, daily briefing
  Domus, what do I need to do today?


5. MEAL SUGGESTIONS
-------------------
Suggests meals from a built-in food database (18 seeded dishes). Avoids meals
eaten in the last 2 days. Shows prep time, notes, and which ingredients you
already have on the shopping list.

Examples:
  Domus, what should I eat for dinner?
  Domus, what can I eat for lunch?
  Domus, meal idea


6. COOK THIS → UPDATE SHOPPING LIST (plan_meal)
-----------------------------------------------
Pick a meal and Domus adds only the missing ingredients to the shopping list.

Examples:
  Domus, let's make curry with rice tonight
  Domus, I want to cook shakshuka
  Domus, make pasta aglio e olio

Reply example:
  Planning "Curry with rice": Added to the shopping list: coconut milk, curry
  paste. You already have: rice, vegetables.


7. WEEKLY MEAL PLAN
-------------------
Plans one dinner per remaining day from today through Sunday. Saves the plan,
shows it on request, and adds all missing ingredients for the week to the
shopping list (deduplicated).

Examples:
  Domus, plan meals for this week
  Domus, show the meal plan
  Domus, what's the meal plan this week?


8. WHAT'S MISSING FOR DINNER?
-----------------------------
Read-only check: compares a meal's ingredients against the open shopping list
without adding anything.

Examples:
  Domus, what's missing for pasta aglio e olio?
  Domus, what's missing for dinner?
  (If no meal is named, uses tonight's planned meal from the weekly plan.)


9. LOG MEALS
------------
Remembers what you ate so suggestions vary over time.

Examples:
  Domus, I had pasta for dinner
  Domus, we ate shakshuka


10. CONVERSATION LOGS
---------------------
Each bot session writes an append-only log to logs/session_YYYY-MM-DD_HH-MM-SS.log
(format: timestamp, user message — bot response). Logs are gitignored.


11. LIFECYCLE MESSAGES
----------------------
When the bot starts:  "Hi, I am awake and ready."
When the bot stops:   "Goodbye, I am going to sleep now."
(Sent to all subscribed group chats.)


12. INFRASTRUCTURE (behind the scenes)
--------------------------------------
  - Telegram polling (no public server required)
  - SQLite database with tables: todos, reminders, foods, meal_history,
    meal_plans, notification_chats (+ unused schema for meals, expenses)
  - APScheduler via python-telegram-bot job queue:
      * due-date reminders every 60s
      * recurring reminders every 60s
      * morning briefing daily at BRIEFING_HOUR (default 8)
  - OpenRouter intent routing (default model: meta-llama/llama-3.2-3b-instruct)
  - Regex / rule-based fallback when OpenRouter is unavailable
  - 45-second message timeout with user-friendly error
  - Long replies split at Telegram's 4096-character limit


RECENT IMPROVEMENTS (from session log review, Aug 2026)
-------------------------------------------------------
Fixed issues seen in logs/session_2026-08-23_17-58-07.log:

  1. "add … to the todo list. Have to do it tomorrow" now picks up tomorrow
     from the second sentence and sets the correct due date.

  2. Todo-list adds no longer default to category "shopping" — errands like
     "going to the bank" are categorized as admin.

  3. "I said the task is for tomorrow" is handled as update_todo instead of
     triggering a hallucinated new task from OpenRouter few-shot examples.

  4. "I meant going to the bank" clarifies the intended task and removes
     mistaken entries when possible.

  5. Removed misleading few-shot example from the OpenRouter system prompt;
     corrections are parsed by rules before the LLM is consulted.

6. QUICK "DONE WITH RECURRING TASK" ACK
   Command: "Domus, done with trash" after a recurring reminder fires

   Daily cron or PTB job: copy data/domus.db to data/backups/domus_YYYY-MM-DD.db
